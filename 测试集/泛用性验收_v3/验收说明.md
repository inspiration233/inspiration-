# 泛用性验收测试集 v3

本目录用于描述产品应当处理的输入、反馈和预期结果。夹具自检检查这些材料自身是否一致；通过不代表当前产品引擎已实现拆分、反馈合并或保真要求。

## 使用

依赖 Python 3.10+ 和 openpyxl 3.1.x。命令在本目录运行。

```text
python 自检.py --quiet
python 重建验证.py
python 验证检查器.py
```

- `自检.py`：检查当前文件，失败返回非零退出码。省略 `--quiet` 查看逐项结果；用 `--json 报告.json` 保存分类报告。
- `重建验证.py`：在空临时目录完整生成、自检，再与本目录比较。不修改正式夹具。
- `验证检查器.py`：在临时副本中故意改错数据、公式或保真属性，验证检查器会拒绝错误文件。

修改生成逻辑后，用以下命令更新正式夹具：

```text
python 重建验证.py --update
```

只有临时重建和自检成功后才同步生成文件，移除过期生成工作簿。其他文档和用户文件不在同步范围内。重建比较检查文件清单、JSON、XLSX内的公式、数据、样式、关系、验证及条件格式；只忽略ZIP封装和文档创建/修改时间。

底层生成顺序仍为：

```text
python 生成验收集.py
python 补充案例.py
python 修订.py
python 收尾修订.py
python 自检.py
```

`收尾修订.py` 最后调用 `原生保真.repair`。`验收断言.py` 独立读取文件和业务基线，不调用产品引擎或生成函数，不采信历史“通过”快照。

W2月度、W6月度是内容预期表，用于核对任务及数值；它们不构成全部原生排版属性的验收标准。W1/W3原生属性有独立断言和可读的 `fidelity_contract`。其他布局的原生保真验收仍需补充。

## 如何理解报告

报告区分文件结构、业务数据、保真属性、检查覆盖、业务待确认和实机验证。不同类别的通过次数不能相加后称为“全部业务场景通过”。

- 文件可读和文件存在只证明材料齐全。
- 内容与保真检查直接读取当前工作簿；缺任务、错字段、错公式、错误范围或属性均产生失败。
- 尚未实现的自动断言记为跳过，并明确为检查覆盖不足。已有文字真值也不等于已经自动验证。
- 业务问题保留在对应案例中。W2总计处理及W6月份归属仅是本案例采用的前提，不能替代产品需求决策。
- Excel/WPS中的实际重算、下拉交互、条件格式显示及打印效果尚需实机检查。静态检查成功不能代替这些检查。

其余结构、关系、反馈、保真和RT42案例仍作为待接入产品验收的材料保留。当前没有对全部42案例执行产品引擎，也没有宣称全部原生能力已实现。运行结果以当次分类报告为准，不在文档中固化易过期的通过数量。
